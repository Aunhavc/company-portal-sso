# วิธีเพิ่มแอปใหม่เข้าหน้า Portal

ออกแบบให้ **ไม่ต้องแก้โค้ดและไม่ต้อง deploy ใหม่** เพิ่มกี่แอปก็ได้

---

## วิธีที่ 1 — จากหน้าเว็บ (ใช้ประจำวัน)

1. ล็อกอินด้วยบัญชีที่มี role = `admin`
2. เมนูบน → **จัดการแอป** (หรือปุ่ม **เพิ่มแอป** บนหน้าหลัก)
3. กด **เพิ่มแอปใหม่** → กรอกฟอร์ม → **เพิ่มแอป**
4. แอปขึ้นหน้าหลักให้พนักงานทุกคนทันที ไม่ต้อง deploy

### คำอธิบายแต่ละช่อง

| ช่อง | ต้องกรอก | คำอธิบาย |
|---|---|---|
| **ชื่อแอป** | ✔ | ชื่อที่พนักงานเห็นบนการ์ด |
| **รหัสอ้างอิง (slug)** | ✔ | ระบบเติมให้อัตโนมัติจากชื่อ · ห้ามซ้ำกับแอปอื่น |
| **คำอธิบาย** | | ข้อความ 1–2 บรรทัดใต้ชื่อ |
| **หมวดหมู่** | | ใช้จัดกลุ่มการ์ด · พิมพ์ชื่อใหม่ได้เลย หรือเลือกจากที่มีอยู่ |
| **ลำดับการแสดง** | | ตัวเลข เลขน้อยขึ้นก่อน (ค่าเริ่มต้น 100) |
| **แอปนี้อยู่ฝั่งไหน** | ✔ | ⬅ ตัวเลือกสำคัญที่สุด ดูตารางด้านล่าง |
| **URL ปลายทาง** | ✔ | ที่อยู่เมื่อคลิกการ์ด ต้องขึ้นต้นด้วย `http://` หรือ `https://` |
| **URL สำหรับเข้าผ่าน SSO** | | ถ้ากรอก ระบบจะพาไป URL นี้แทน เพื่อล็อกอินอัตโนมัติก่อนเข้าหน้างาน |
| **URL ตรวจสอบสถานะ** | | ถ้ากรอก การ์ดจะมีไฟเขียว/เทาบอกว่าเข้าถึงได้ไหม · มีปุ่ม **ทดสอบ** ในฟอร์ม |
| **เปิดในแท็บใหม่** | | ปิดไว้สำหรับแอปที่ต้องทำ SSO redirect |
| **ไอคอน / สีเน้น** | | เลือก emoji และสี · มีตัวอย่างการ์ดให้ดูสดในฟอร์ม |
| **ใครเห็นแอปนี้ได้** | ✔ | ติ๊ก "พนักงานทั่วไป" ออก = เห็นเฉพาะผู้ดูแลระบบ (บังคับที่ฐานข้อมูลด้วย ไม่ใช่แค่ซ่อน UI) |
| **เปิดใช้งาน** | | ปิดเพื่อซ่อนชั่วคราวโดยไม่ต้องลบ |

### เลือก "ฝั่งไหน" ยังไง

| | ระบบบนคลาวด์ (internet) | ระบบภายในองค์กร (intranet) |
|---|---|---|
| เข้าจากบ้านได้ไหม | ได้ | ต้องต่อ VPN ก่อน |
| ป้ายบนการ์ด | ฟ้า "ใช้งานได้ทุกที่" | เขียว "เชื่อมต่อแล้ว" / เทา "ยังไม่ได้ต่อ VPN" |
| คลิกตอนเข้าไม่ถึง | เปิดไปเลย | เปิดหน้าต่างสอนวิธีต่อ VPN |
| ควรกรอก URL ตรวจสอบสถานะ | ไม่จำเป็น | **ควรกรอก** |

## ตัวอย่างการกรอก

### แอปคลาวด์ธรรมดา
```
ชื่อ            ระบบจัดซื้อออนไลน์
ฝั่ง            ระบบบนคลาวด์
URL             https://purchase.company.com
เปิดแท็บใหม่     ✔
```

### แอปภายในที่ทำ SSO ได้ (แบบเดียวกับ ERP ในเอกสารต้นฉบับ)
```
ชื่อ            ระบบ ERP
ฝั่ง            ระบบภายในองค์กร
URL             https://erp.company.local/dashboard.php
URL SSO         https://erp.company.local/auth-callback.php
URL ตรวจสถานะ    https://erp.company.local/ping.php
เปิดแท็บใหม่     ✘  (ต้องปิด เพราะมีการ redirect ไป Auth0 แล้วกลับ)
```

### แอปภายในที่ยังไม่ได้ทำ SSO
```
ชื่อ            ระบบคลังสินค้า
ฝั่ง            ระบบภายในองค์กร
URL             https://wms.company.local/
URL SSO         (เว้นว่าง — ผู้ใช้จะล็อกอินด้วยระบบเดิมของแอปนั้น)
URL ตรวจสถานะ    https://wms.company.local/ping.php
```

## วิธีที่ 2 — ใส่ผ่าน SQL (เหมาะกับการเพิ่มทีละหลายรายการ)

Supabase → SQL Editor:

```sql
insert into public.apps
  (slug, name, description, category, network, url, sso_url, health_url,
   icon, accent, open_in_new_tab, allowed_roles, sort_order)
values
  ('purchase', 'ระบบจัดซื้อออนไลน์', 'ขออนุมัติและติดตามสถานะใบสั่งซื้อ',
   'จัดซื้อ', 'internet', 'https://purchase.company.com', null, null,
   '🧾', 'cyan', true, array['user','admin'], 50);
```

ค่าที่ใช้ได้:
- `network` → `internet` | `intranet`
- `accent` → `slate` `blue` `emerald` `amber` `rose` `violet` `cyan` `orange`
- `allowed_roles` → `array['user','admin']` หรือ `array['admin']`

## ทำระบบภายในให้แสดงไฟเขียวได้

คัดลอก `php-intranet/ping.php` ไปวางที่ราก document root ของแอปนั้น แล้วเพิ่ม
origin ของ Portal ลงใน `portalOrigins` ใน `config.php`

ถ้าแอปนั้นไม่ใช่ PHP ให้ทำ endpoint ที่ตอบ HTTP 200 พร้อม header เหล่านี้ก็พอ:

```
Access-Control-Allow-Origin: https://portal.company.com
Vary: Origin
Content-Type: application/json
Cache-Control: no-store
```

> **ต้องเป็น HTTPS** ถ้า endpoint เป็น `http://` เบราว์เซอร์จะบล็อกเพราะ Mixed Content
> การ์ดจะขึ้นป้ายเหลือง "ตรวจสอบไม่ได้" พร้อมอธิบายสาเหตุ — ดูวิธีแก้ที่ `PLAN.md` เฟส 5
