## A. Portal (โหมดสาธิต — ยังไม่ต้องมี Auth0/Supabase)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| A1 | `cd web && npm install && npm run dev` | เปิด `http://localhost:5173` เห็นหน้า Portal พร้อมแบนเนอร์ "โหมดสาธิต" |
| A2 | ดูการ์ดแอป | เห็น 5 การ์ด แบ่งกลุ่มตามหมวดหมู่ |
| A3 | คลิกการ์ด ERP (ระบบภายใน) | ไปหน้ากลาง `/launch/erp` แล้วขึ้นหน้าแจ้งให้ต่อ VPN (ไม่ใช่หน้า error ของเบราว์เซอร์) |
| A4 | ค้นหา + สลับตัวกรอง คลาวด์/ภายใน | รายการเปลี่ยนตามเงื่อนไข |
| A5 | คลิกประกาศข่าวสาร | เปิด modal อ่านเนื้อหาเต็ม |
| A6 | เมนู → จัดการแอป → เพิ่มแอปใหม่ | เพิ่มแล้วขึ้นในตารางและหน้าหลักทันที |
| A7 | สลับสวิตช์ปิดใช้งานแอป | การ์ดหายจากหน้าหลัก แต่ยังอยู่ในตาราง Admin |
| A8 | ย่อจอเป็นขนาดมือถือ | ทุกอย่างอ่านได้ ไม่มี scroll แนวนอน |

## B. Auth0 + Supabase (โหมดจริง)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| B1 | เติม `.env` ครบ 5 ตัวแล้วรีสตาร์ท dev server | แบนเนอร์โหมดสาธิตหายไป |
| B2 | เปิดหน้าแรก | เด้งไปหน้า Universal Login ของ Auth0 |
| B3 | ล็อกอินด้วยบัญชีทดสอบ | กลับมาที่ Portal พร้อมชื่อ+รูปบนแถบบน |
| B4 | Supabase → Table Editor → `profiles` | มีแถวใหม่ `id` ขึ้นต้นด้วย `auth0\|` |
| B5 | DevTools → Network → ดู request ไป Supabase | มี header `Authorization: Bearer eyJ…` (เป็น JWT ไม่ใช่ opaque) |
| B6 | ล็อกอินด้วยบัญชีที่ role = `user` | **ไม่เห็น** เมนู "จัดการแอป" และไม่เห็นการ์ด Admin Console |
| B7 | บัญชี `user` พิมพ์ `/admin/apps` ตรง ๆ | ถูกส่งกลับหน้าหลัก |
| B8 | รัน `0003_make_admin.sql` แล้วรีเฟรช | เห็นเมนูจัดการแอป |
| B9 | บัญชี `user` ลอง `update profiles set role='admin'` ผ่าน DevTools | role ไม่เปลี่ยน (trigger กันไว้) |
| B10 | กด "ออกจากระบบ" | กลับหน้าล็อกอิน · กด Back แล้วเข้าไม่ได้ |

## D. การเชื่อมสองฝั่ง (ข้อสำคัญที่สุด)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| D0 | หน้าจัดการแอป → ตั้งค่าองค์กร | ช่อง "ชื่อ DynDNS / IP สาธารณะของบริษัท" มีชื่อครบ **ทุก WAN** ที่บริษัทใช้ออกเน็ต |
| D1 | อยู่ใน LAN สำนักงาน → คลิกการ์ดระบบภายใน | เข้าแอปทันที (หน้ากลางขึ้นแค่ "กำลังพาเข้า …" แวบเดียว) |
| D2 | **ตัด VPN / ใช้เน็ตนอกสำนักงาน** แล้วคลิกการ์ด | หน้าเหลือง "คุณอยู่นอกเครือข่ายบริษัท — ต้องเชื่อมต่อ VPN ก่อนใช้งาน" **ห้ามเจอ error ของเบราว์เซอร์** |
| D3 | กดปุ่ม "ต่อ VPN แล้ว ตรวจสอบอีกครั้ง" ทั้งที่ยังไม่ได้ต่อ | หัวข้อเปลี่ยนเป็น "ตรวจแล้ว ยังไม่พบการเชื่อมต่อ VPN…" พร้อมกรอบเน้น — ห้ามค้างหน้าเดิมเงียบ ๆ |
| D4 | **ต่อ VPN (full-tunnel)** → เปิด `https://api.ipify.org` | ต้องได้ IP สาธารณะของบริษัท ไม่ใช่ IP บ้าน/มือถือ |
| D5 | คลิกการ์ดตอนต่อ VPN แล้ว | เข้าแอปทันที · ถ้าแอปทำ SSO ต้องเข้าได้ **โดยไม่ถามรหัสผ่าน** |
| D6 | ทดสอบซ้ำด้วย **Chrome** | ถ้ากดการ์ดแล้วเงียบ = ตัวบล็อกป๊อปอัป (การ์ดตั้ง "เปิดในแท็บใหม่") |
| D7 | ถ้าการ์ดขึ้นสีเหลือง "ตรวจสอบไม่ได้" | แปลว่ากรอก `health_url` เป็น HTTP → เว้นว่างไว้จนกว่าจะทำเฟส 5 เสร็จ |

รายละเอียดการตั้งค่าและวิธีไล่ปัญหา: `NETWORK-CHECK-AND-VPN.md`

## E. ความปลอดภัย (ตรวจก่อนเปิดใช้จริง)

- [ ] เปิด DevTools → Application → ยืนยันว่า **ไม่มี** service role key ของ Supabase ใน bundle
- [ ] ยิง `curl https://<project>.supabase.co/rest/v1/profiles?select=*` ด้วย anon key เปล่า → ต้องได้ `[]` (RLS ทำงาน)
- [ ] `config.php` ของ PHP **ไม่ได้** ถูก commit เข้า git
- [ ] `.env` **ไม่ได้** ถูก commit เข้า git
- [ ] ping.php ตอบ CORS เฉพาะ origin ของ Portal (ทดสอบด้วย `curl -H "Origin: https://evil.com" .../ping.php -i`)
- [ ] Auth0 ปิด Sign Ups แล้ว
- [ ] เปิด MFA แล้ว (ถ้านโยบายบริษัทกำหนด)

## F. ประสิทธิภาพ

- [ ] Lighthouse (มือถือ) ≥ 90 ทั้ง Performance และ Accessibility
- [ ] หน้าแรกโหลดเสร็จภายใน 2 วินาทีบน 4G
- [ ] probe ที่ล้มเหลวไม่ทำให้หน้าเว็บค้าง (timeout 2.5 วินาที)
