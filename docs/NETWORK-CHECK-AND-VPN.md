# การตรวจเครือข่ายบริษัท และการต่อ VPN จากภายนอก

เอกสารนี้อธิบายว่า **พอร์ทัลรู้ได้อย่างไรว่าเครื่องผู้ใช้อยู่ในเครือข่ายบริษัท** และ
**ต้องต่อ VPN แบบไหนจึงจะใช้งานระบบภายในผ่านพอร์ทัลได้**

ปรับปรุงล่าสุด: 8 กันยายน 2569 — ทดสอบจริงครบทุกกรณีแล้ว

---

## 1. ปัญหาที่ต้องแก้ และข้อกำหนด

ข้อกำหนดจากผู้ใช้งาน (ห้ามละเมิด):

> คลิกการ์ดระบบภายในแล้ว **ห้าม**เจอ 2 อย่างนี้เด็ดขาด
> 1. หน้า error ของเบราว์เซอร์ ("This site can't be reached" / 404)
> 2. เงียบไปเฉย ๆ โดยไม่บอกสาเหตุ
>
> ถ้าต่อไม่ถึงไม่ว่าด้วยเหตุใด ต้องขึ้นหน้าจอ **แจ้งให้ต่อ VPN** เสมอ

อุปสรรคทางเทคนิค: พอร์ทัลรันบน **HTTPS** (Vercel) แต่ระบบภายในยังเป็น **HTTP**
เบราว์เซอร์จึงบล็อกทุกวิธีที่จะยิงไปตรวจว่าเครื่องเข้าถึง `192.168.0.x` ได้หรือไม่ (Mixed Content)
→ **ตรวจตรง ๆ ไม่ได้**

## 2. วิธีที่ใช้จริง — เทียบ IP สาธารณะกับชื่อ DynDNS ของบริษัท

เครื่องที่อยู่ในสำนักงาน หรือเครื่องที่ต่อ VPN แบบ **full-tunnel**
จะออกอินเทอร์เน็ตด้วย **IP สาธารณะของบริษัท** เสมอ → ใช้ข้อเท็จจริงนี้เป็นตัวตัดสิน

```
เบราว์เซอร์ ── GET /api/network-check?host=… ──► Vercel Function
                                                  │
                          อ่าน IP ผู้เรียกจาก x-forwarded-for
                          resolve ชื่อ DynDNS ของบริษัท (A + AAAA)
                                                  │
                          IP ตรงกัน → inside:true ─┘
```

| ผลตรวจ | หน้าจอที่ผู้ใช้เห็น |
|---|---|
| `inside: true` | "กำลังพาเข้า …" แล้วเข้าแอปทันที |
| `inside: false` | หน้าเหลือง "คุณอยู่นอกเครือข่ายบริษัท — ต้องเชื่อมต่อ VPN ก่อนใช้งาน" + ขั้นตอนต่อ VPN + ปุ่มตรวจซ้ำ |
| เรียก API ไม่ได้ | หน้าแดง "ตรวจสอบเครือข่ายไม่สำเร็จ" + ปุ่มลองใหม่ |
| ผู้ดูแลยังไม่ตั้งค่าโฮสต์ | หน้าฟ้า บอกว่าตรวจให้ไม่ได้ + ให้ผู้ใช้ยืนยันเอง |

กดปุ่ม "ต่อ VPN แล้ว ตรวจสอบอีกครั้ง" รอบที่ 2 ขึ้นไปแล้วยังไม่ผ่าน
หัวข้อจะเปลี่ยนเป็น **"ตรวจแล้ว ยังไม่พบการเชื่อมต่อ VPN — กรุณาตรวจสอบการเชื่อมต่อ VPN อีกครั้ง"**
พร้อมกรอบเน้นสี เพื่อไม่ให้ผู้ใช้เข้าใจว่าปุ่มเสีย

## 3. ค่าที่ต้องตั้ง (สำคัญที่สุดในเอกสารนี้)

**หน้าจัดการแอป → การ์ด "ตั้งค่าองค์กร" → ช่อง "ชื่อ DynDNS / IP สาธารณะของบริษัท"**

```
somjai001.dyndns.biz somjai002.dyndns.biz
```

| ชื่อ | ชี้ไปที่ | WAN | ผู้ให้บริการ | interface บน Zyxel | ใครออกทางนี้ |
|---|---|---|---|---|---|
| `somjai001.dyndns.biz` | 119.76.173.14 | WAN1 | True | `ge2_ppp` | เครื่องที่อยู่ใน LAN สำนักงาน |
| `somjai002.dyndns.biz` | 180.183.244.119 | WAN2 | 3BB | `ge1_ppp` | เครื่องที่ต่อ **SSL VPN** |

> **ต้องมีครบทั้งสองชื่อ** ไฟร์วอลล์มี WAN สองเส้นและออกเน็ตคนละเส้นกัน
> ถ้าใส่ชื่อเดียว ผู้ใช้ VPN จะโดนหน้าเหลืองทั้งที่ต่อ VPN แล้ว

ใส่เป็นเลข IP ตรง ๆ ก็ได้ (ระบบรับทั้งชื่อโฮสต์และ IP) แต่ **ไม่ควรทำ** เพราะทั้งสอง WAN เป็น IP แบบไดนามิก

## 4. VPN ที่ใช้ได้จริงคือ SSL VPN ไม่ใช่ L2TP

| แบบ | สถานะ | หมายเหตุ |
|---|---|---|
| **SSL VPN (Zyxel SecuExtender)** | ✅ ใช้งานจริง | ต่อได้ทุกเครือข่าย ผ่าน TCP 443 ไม่ติดปัญหา UDP ของเน็ตมือถือ |
| L2TP/IPsec (VPN ในตัว Windows) | ❌ เลิกใช้ | ต่อไม่ติด (error 809/628) — รายละเอียดในหัวข้อ 7 |

### ต้องเป็น full-tunnel เท่านั้น

split-tunnel จะส่งเฉพาะ traffic ที่วิ่งเข้า LAN บริษัทผ่านทันเนล
ส่วนอินเทอร์เน็ตยังออกทางบ้าน → **IP สาธารณะไม่เปลี่ยน → พอร์ทัลตรวจไม่เจอ**

เปิด full-tunnel ที่:

```
Zyxel USG FLEX 700 (192.168.0.254)
  CONFIGURATION → VPN → SSL VPN → แท็บ Access Privilege
    → นโยบาย SSL_VPN → Edit
      → หัวข้อ Network Extension (Full Tunnel Mode)
        ☑ Force all client traffic to enter SSL VPN tunnel
```

- กล่องเตือน *"The device will ignore your Network List settings"* เป็นเรื่องปกติ กด OK ได้
  (full-tunnel ส่งทุกอย่างเข้าทันเนลอยู่แล้ว สิทธิ์เข้า `192.168.0.x` ไม่หาย)
- ผลข้างเคียง: อินเทอร์เน็ตของผู้ใช้ SSL VPN ทุกคนจะวิ่งผ่านสำนักงาน (ช้าลง + โหลด WAN เพิ่ม)
- เซสชันที่ต่ออยู่เดิมต้อง **ตัดแล้วต่อใหม่** จึงจะได้ route ใหม่

## 5. แก้ปัญหาผู้ใช้หลุดแล้วกลับเข้าไม่ได้

อาการ: ผู้ใช้หลุดจาก SSL VPN แบบไม่ปกติ (เน็ตหลุด/ปิดฝาโน้ตบุ๊ก) แล้วล็อกอินใหม่ไม่ได้

สาเหตุ: เซสชันซากยังถูกนับอยู่ และอุปกรณ์ตั้งให้ **Block** คนที่เข้ามาใหม่

แก้ที่:

```
CONFIGURATION → Object → User/Group → แท็บ Setting
  → หัวข้อ User Logon Settings
    ☑ Limit the number of simultaneous logons for access account
       Maximum number per access account: 1
       Reach maximum number per account:  ○ Block  ⦿ Remove previous   ← เปลี่ยนเป็นอันนี้
```

- คงลิมิต 1 เซสชันไว้ (กันใช้บัญชีร่วมกัน) แต่ให้การล็อกอินใหม่เตะเซสชันเก่าทิ้งเอง
- **ไม่แนะนำ** ให้เพิ่ม Maximum เป็น 2 และไม่ต้องเปิด "Enable user idle detection"
- ถ้าต้องเตะด้วยมือ: `MONITOR → VPN Monitor → SSL` เลือกแถว → **Disconnect**

## 6. วิธีทดสอบ

### 6.1 ทดสอบเร็วโดยไม่ต้องต่อ VPN

API รับ IP ตรง ๆ ได้ จึงจำลองกรณี "อยู่ในเครือข่าย" ได้ทันที:

```bash
IP=$(curl -s https://api.ipify.org)
curl -s "https://company-portal-sso.vercel.app/api/network-check?host=$IP"
# ต้องได้ inside:true
```

### 6.2 ทดสอบของจริง 3 กรณี (เช็กลิสต์ก่อนส่งมอบ)

| # | สภาพเครื่อง | ผลที่ต้องได้ |
|---|---|---|
| 1 | อยู่ใน LAN สำนักงาน | กดการ์ด → เข้าแอปทันที |
| 2 | อยู่นอกสำนักงาน ไม่ต่อ VPN | หน้าเหลืองแจ้งให้ต่อ VPN **ห้ามมี error ของเบราว์เซอร์** |
| 3 | ต่อ SSL VPN (full-tunnel) | กดการ์ด → เข้าแอปทันที |

ตรวจ IP ขาออกก่อนเสมอ — เปิด `https://api.ipify.org` ต้องได้
`119.76.173.14` (ใน LAN) หรือ `180.183.244.119` (ผ่าน SSL VPN)
ถ้าได้ IP ของบ้าน/มือถือแปลว่ายังเป็น split-tunnel

### 6.3 ตรวจว่า DDNS ยังอัปเดตอยู่

```
MONITOR → Network Status → DDNS Status
```

ทั้ง `DDNS_True` (somjai001) และ `DDNS_3BB` (somjai002) ต้องขึ้น **Success** พร้อม Effective IP ที่ถูกต้อง
โปรไฟล์ที่เพิ่งสร้างใหม่จะขึ้น *Fail* จนกว่าจะเลือกแถวแล้วกดปุ่ม **Update** เองหนึ่งครั้ง

## 7. บันทึกการแก้ปัญหาที่เคยเจอ (กันเสียเวลาซ้ำ)

| อาการ | สาเหตุจริง | ทางแก้ |
|---|---|---|
| กดการ์ดบน Chrome แล้วเงียบ แต่ Firefox เข้าได้ | การ์ดตั้ง "เปิดในแท็บใหม่" → `window.open()` โดน **popup blocker** | อนุญาตป๊อปอัปของโดเมนพอร์ทัล หรือแก้การ์ดเป็นเปิดในแท็บเดิม |
| ต่อ VPN แล้วพอร์ทัลยังบอกว่าอยู่นอกเครือข่าย | split-tunnel หรือออกทาง WAN ที่ยังไม่ได้ลงทะเบียน | ดูหัวข้อ 3 และ 4 |
| `rasdial` ขึ้น **error 623** | ชื่อโปรไฟล์ไม่ตรง (เครื่องมีโปรไฟล์ชื่ออื่น) | `Get-VpnConnection` ดูชื่อจริงก่อน |
| L2TP ขึ้น **error 809** | ค่า `ProhibitIpSec = 1` ในรีจิสทรีทำให้ Windows ข้าม IPsec แล้วยิง L2TP เปล่าไป UDP 1701 ไฟร์วอลล์จึงทิ้ง | ตั้ง `HKLM\SYSTEM\CurrentControlSet\Services\Rasman\Parameters\ProhibitIpSec = 0` และ `…\PolicyAgent\AssumeUDPEncapsulationContextOnSendRule = 2` แล้วรีบูต (แก้แล้วก็ยังไม่ติด — จึงเปลี่ยนไปใช้ SSL VPN) |
| L2TP ขึ้น **error 628** | IPsec ผ่านแล้วแต่ถูกตัดตอนยืนยันตัวตน | ต้องตรวจสิทธิ์บัญชีฝั่งไฟร์วอลล์ |
| `/api/network-check` ตอบ `FUNCTION_INVOCATION_FAILED` | `web/package.json` เป็น `"type": "module"` → Vercel รัน `api/*` เป็น ESM ซึ่ง import แบบไม่มีนามสกุลไม่ได้ | ใส่ `.js` ท้าย path ที่ import |

### เครื่องมือที่ใช้ไล่ปัญหาได้ผลจริง

- **log ของ Zyxel** `MONITOR → Log → View Log` → **Show Filter**
  ตั้ง **Category = All Logs** (ถ้าเลือก IKE อย่างเดียวจะไม่เห็นรายการที่ Security Policy ทิ้ง)
  แล้วใส่ IP ต้นทางของเครื่องที่ทดสอบ
  ⚠️ log เก็บได้แค่ประมาณ **5 นาที** (2048 บรรทัด) ต้องยิงทดสอบแล้วรีบดูทันที
- ดู default route ของเครื่อง: `Get-NetRoute -DestinationPrefix 0.0.0.0/0`
  ถ้ามีสองเส้นแปลว่ายังเสียบสาย LAN อยู่ ผลทดสอบ "จากภายนอก" จะใช้ไม่ได้
